# 美而美 POS · 點餐工作台

網站：https://martyli.github.io/mei-er-mei-pos/

給早餐店櫃檯使用的繁體中文單機網頁 POS。介面參考 iCHEF 公開介紹的「訂單與菜單同畫面、點餐 → 客製 → 結帳、前台與設定分開」流程，以原創視覺與模組實作。並非 iCHEF 的內部系統或官方產品。

## 2026-10-21：減項與會員儲值

### 客製減項

- 「設定 → 加料／減項」可輸入正數或負數：加蛋 `15`、不加蛋 `-15`。
- 新版提供「不加蛋 −$15」預設選項。請在「設定 → 餐點品項 → 編輯 → 適用客製選項」勾選含蛋餐點；系統不猜測每道餐點配方。
- 可設定不可同選的選項；預設加蛋與不加蛋互斥，點選會自動切換。
- 客製調整按每份計算，例如火腿蛋吐司 $40，不加蛋 −$15，兩份共 $50。減項不能讓單份餐價低於零。
- 免費文字備註不改價；價差在點餐、結帳、交易明細及 CSV 都保留正負符號。

### 會員儲值

- 「會員 → 新增會員」填名稱、選填電話，建立獨立帳戶。可填入原有儲值餘額（含負數欠款），以期初紀錄保存，不算今日現金儲值。
- 「會員 → 查看帳戶 → 現金儲值」登記收到的款項，顯示儲值後餘額及完整異動紀錄。
- 結帳選「儲值金」，搜尋並選取會員，再確認扣款。預設扣整筆餐費，允許餘額變成負數。
- 例如餘額 $30、消費 $50，結帳後為 −$20；再儲值 $100，餘額為 $80。畫面以「待補款」標示欠款。
- 需要收現金差額時，可勾選「餘額不足時改用現金補差額」，只扣可用的正餘額；預設不勾選。
- 會員頁分別顯示儲值餘額合計與待補款合計，不把兩者互相抵銷。
- 餐點營業額包含現金和儲值金付款；現金儲值另列統計，避免重複算營業額。帳本記錄每筆期初、儲值及消費扣款，無直接改餘額或刪除帳本入口。
- 單筆儲值上限 $999,999,999，帳戶餘額範圍 −$999,999,999～$999,999,999。此處是店內帳務紀錄，沒有連接銀行、信用卡或線上付款。

### 資料升級

資料格式升為 v3，沿用原本的 `mei-er-mei-pos-v2` 儲存鍵，保留餐點、設定、目前訂單、暫存與歷史交易。升級只新增減項預設及空白會員帳本，既有訂單與交易價格不變。v2 備份可以匯入並升級，v3 備份包含會員與儲值異動。

會員資料與餘額只存於這台裝置的瀏覽器，請固定用同一裝置操作並每日備份；跨裝置不會自動同步。備份含會員姓名、選填電話與帳務，請妥善保管。不要同時用多個分頁結帳。

## 使用方式

- 點餐點名稱開啟客製；點卡片「＋」直接加入原味。
- 預設加料：加蛋 +$15、起司 +$10、肉鬆 +$10。可複選，每份都計入加料費。
- 訂單列可修改加料、備註、份數。不同組合獨立列出，相同組合合併。
- 支援外帶、內用桌號、整單備註及暫存。取回暫存時，正在編輯的非空訂單會自動暫存。
- 現金結帳輸入實收；儲值金付款可選會員扣款，顯示不足或找零；確認後記錄交易並建立下一單。
- 「交易」可查日期、營業額、餐點排行、明細及匯出 CSV。列印內容是交易明細，非統一發票。
- 「設定」可管理餐點、分類、加料／減項名稱與價格、販售狀態；每道餐點可指定適用加料。
- 「設定 → 資料備份」匯出完整 JSON，換裝置時可以還原。

## 資料與相容性

使用目前瀏覽器的 localStorage 儲存，不會跨裝置自動同步。請用固定的正常瀏覽器視窗，建議每天收店下載備份。清除網站資料或瀏覽器資料會移除本機記錄。

首次使用新版會將舊版 `mei-er-mei-menu-v1`、`mei-er-mei-addons-v1` 轉成 v3，保留原菜單與加料價格，並保留舊儲存鍵。舊版未持久化的訂單無法轉移。餐點預設都可加料，飲料預設不提供，可在設定逐項調整。

訂單使用價格快照：修改菜單不回寫目前訂單、暫存與歷史交易的原價。所有金額使用新台幣整數。每列最多 999 份，餐點原價 0～99,999 元，客製調整 −99,999～99,999 元。

本版提供單機現金與會員儲值記帳，沒有金流、電子發票、廚房連線、員工權限、退款或雲端同步。頁面首次載入需網路；不承諾關閉後可離線重新開啟。多分頁同時作業會提示重新載入，建議只開一個點餐分頁。

## 程式結構

| 檔案 | 責任 |
| --- | --- |
| `index.html` | 語意頁面入口與模組載入 |
| `styles.css` | 電腦、平板、手機與列印排版 |
| `app.mjs` | 畫面、表單、互動、匯出與使用者提示 |
| `core.mjs` | 計價、訂單生命週期、會員儲值帳本、交易快照、每日統計與資料驗證 |
| `storage.mjs` | 舊資料轉換、本機儲存、完整備份還原及多分頁衝突檢查 |
| `core.test.mjs` | Node 原生測試，不需額外套件 |

儲存流程：複製狀態 → 套用變更 → 驗證 → 寫入單一 JSON → 更新畫面。寫入失敗時保留前一狀態，不會誤顯示結帳成功。啟動遇到毀損資料會提供原始資料匯出，不自動清空。

靜態 ES modules，無外部套件或追蹤。將上述網站檔案放在 GitHub Pages 根目錄即可部署。用 HTTP/HTTPS 靜態伺服器開啟，不以檔案協定直接開啟。

執行核心測試（Node.js 22 以上）：

```sh
node --test core.test.mjs
```

23 項測試涵蓋菜單轉換、加料與份數、編輯合併、暫存切換、現金驗證、臺北日期換日、儲存失敗、多分頁衝突、有效/無效備份，以及毀損資料保留；另含正負客製價格、互斥選項、v2 升級、會員建檔、儲值防重送、全額與混合付款、負餘額與後續儲值、帳本核對及寫入失敗保留原餘額。另以瀏覽器檢查點餐、結帳、設定保存，及 390px 手機 / 1024px 平板排版。
